# Track 4. Proposal B over Prime

## Summary

**Verdict. Partly.** Prime reduces queue-storage and supervisor-restart work. It does not make full B materially simpler than installed pi-web on the evidence available. Prime's public supervisor has no replayable event history, no durable source-message admission identity, no authoritative terminal-result channel, and no successor child-adoption operation. Its Rust callbacks are embedding APIs, not installable daemon hooks. Installed Pi already has extensive extension hooks, durable conversation trees, a session daemon, and an underlying exact-entry fork.

The important distinction is durable conversation versus durable obligations. Neither backend currently implements B's obligation contract. Prime gets closer on pending-text recovery, but source inspection found that admission discards persistence errors. Its successful acknowledgement is therefore not a strict durability receipt. The real isolated check confirmed two separate gaps. A provider preflight refusal had no assistant transcript row, and an older event cursor returned `event_replay_not_available`.

This is feasibility evidence, not a choice of B for pi-stack. Z17 leaves design open. Z19 drops C and withdraws G24's A/C merge. The requested follow-on design is [41-design-b-prime-detailed.md](41-design-b-prime-detailed.md). Its proposed APIs must not be confused with existing Prime capabilities.

## Minimal prototype and verification

The local branch is `spike/b-over-prime`, created first from `origin/main@3acf0f0`. The throwaway code is `spikes/b-over-prime/{probe.py,test_probe.py,live_check.py,README.md}`. It has no new daemon or package dependency. SQLite is Python's standard-library storage for the experiment, not a production storage choice.

The data shape is `Intake(session, source_kind, source_id, lane, body)`. The journal key is the caller's session/source namespace/message identity. It commits verbatim source, SHA-256, lane, and `dispatch_uncertain` before sending. A matching duplicate returns the recorded disposition; changed text/lane conflicts. A lost response remains uncertain and is never automatically resent. A native failure is retained as rejected. A native success is admitted, never semantic completion. These ids are explicitly not Prime transcript-entry ids.

This establishes a cooperating-client instrument only. Another TUI/socket/internal producer can bypass it. Its commit and Prime's acceptance are separate transactions. It cannot enforce B1/B4's authoritative contract, perform native adoption, or prove a successful last-good checkpoint. No last-good file was generated after a failed preflight.

## Effort, risks, and verdict

Planning estimates below are guesses in engineer-days for one maintainer familiar with the backend. Both columns include pi-stack adapters and deterministic boundary tests, use the same scope, and exclude rollout, upstream acceptance delays, credential availability, and empirical semantic-review evaluation. They are not default runtime budgets. B4 includes implementing and testing successor adoption; an implementation that visibly refuses adoption costs less but is not full B.

| Mechanism | B over Prime | B over installed pi-web | Main reason |
|---|---|---|---|
| B1 | 5-9 | 5-8 | Prime reuses journal writes but needs native all-producer integration, strict errors, complete payloads, and durable source correlation. Pi-web needs durable ingress but has more integration hooks. |
| B2 | 2-4 | 2-4 | Same projection, retained evidence, Z15 rotation, and per-turn loading checks. |
| B3 | 4-7 | 4-7 | Same source-bound acceptance, pinned results, legitimate alternatives, and false-rejection tests. |
| B4 | 12-22 | 10-20 | Prime saves queue/restart machinery and an exposed exact-entry command. It needs native terminal-result/maintenance work and callback composition. Both need genuine adoption and writer-transfer qualification. |
| B5 | 0.5-1 | 0.5-1 | Same short authority/reporting rules. |
| B6 | 1-2 | 1-2 | Same task-method work; Prime additionally needs deliberate process-skill translation within this range. |
| Total | 24.5-45 | 22.5-42 | Overlapping ranges. No evidence supports a large overall Prime cost advantage. |

B4's uncertain work is dominated by the recovery boundary and child transfer, not subscribing to events. An early deliverable can omit adoption and remain explicitly parked for that case. It must not be described as full Z11 recovery. The detailed plan separates that gate.

The principal risks are these.

- Native-fork maintenance. Authoritative Prime B1/B4 requires changes in pa-types/pa-daemon and selected pa-core wiring, not only a pi-stack client. Upstream acceptance could remove that fork burden; a socket shim cannot remove the semantic gap.
- Moving nightly behavior. N adds child cancellation and a default Python watchdog without changing protocol 7/schema 30. Pin source/build identities and negotiate explicit semantic capabilities. D1 requires disabling imported default resource caps rather than assuming protocol parity.
- Lost outcomes. Sequenced live events and best-effort semantic ledgers cannot be the sole authority. Persist terminal results before publication and query them after a gap.
- Split authority. An external service with its own obligations database becomes a second receiving authority and conflicts with B1. Keep the experiment disposable. Production ownership belongs in the existing service.
- Hidden workflow engine. Reject a task-kind phase registry, configurable DAG scheduler, and plugin-defined transitions. Adding a task should add source and evidence, not a runtime phase.
- Semantic error. Source hashes and correct record transitions cannot prove that the checker asks the right question. F4/F5/F10 still require actual invocation and original-source review.
- Effects and retention. Forking text does not roll back jobs or repository mutation. A streaming flag does not authorize deleting the failed original. Preserve post-checkpoint stops and evidence and require quiescence/adoption before owner transfer.

**Plain answer. Partly, but not materially simpler overall.** Prime is simpler for the pending-input/restart portion of B4 and already exposes exact-entry fork at its supervisor. Rows B1, B2, B3, cancellation, completion admission, and child adoption remain substantially the same work or require deeper native changes. Pi's installed hooks and SDK exact fork offset Prime's queue advantage. ZF's durability hypothesis is supported narrowly, not as a full-B shortcut.

The G24 question is now historical because Z19 withdrew that merge draft. For A as it now stands, the implication survives. Intake-written source identities still need a receiving-side hook; a Markdown row or skill cannot detect an ask that never received a row. The small intake contract and portable checker can be shared between an A implementation and B without choosing B's runtime task authority. This does not select A either.

## Decisions

- Use stable v0.10.1 for isolated controls and inspect both revisions. The moving nightly is not silently treated as the tested binary.
- Prototype an external source-keyed shim, not a Prime fork. It cheaply tests admission and outcome observation while exposing its own bypass and uncertainty limits.
- Persist uncertainty before sending and never auto-resend it. Prime lacks a durable queryable deduplication key for reconciliation.
- Do not generate last-good from the failed preflight. There is no successful complete checkpoint to certify.
- Put current asks under Goals in the follow-on Z15 projection. This preserves exactly three top-level sections and keeps open asks outside Log rotation.
- Prefer native admission/result changes for an authoritative B candidate. This is a within-spike design call, not a pi-stack selection.
- Keep unsupported adoption held and preserve the original. Source replacement currently closes children rather than transferring watches.
- Apply Build the Lever through committed offline/live probes, Model the Domain through the typed intake/disposition model, Make Operations Idempotent through uncertainty retention, and Prove It Works through direct socket and restart readback.
- Keep all reports/data in `/tmp` and both shared artifacts uncommitted. Only spike code and small progress/reference files belong in local Git commits.
- Same-model investigators and parent source checks replace cross-model review under the user's restriction. The orchestration host returned launch stubs before actual children finished; their reports were consumed only after the real completion notices, not trusted from the stub.
- The requested `deslop` leaf was not installed in the searched plugin/agent roots. A manual diff/comment check was used without changing protected plugin state. No PR or publication step applies.
