# Stream

Pass the supplied arguments to `pi-streams`. In a stream role, read AGENTS.md and STATE.md. Goals and Log replace TODO.md and PLAN.md.

## New and status

Run `pi-streams new <id>`. Report its URL and full coordinator ID. Forward supplied ZF orders or Grok Bot relays through `pi-streams delivery send` with a stable delivery ID. Start authorized work without another interview. Retain source provenance. North Star and Charter do not change without authority.

Run `pi-streams status [<id>]` only when observation helps. It returns partial saved facts and a non-opening roster; unknown costs or timeout warnings do not block task admission. Use its threadSessions view rather than engine registries. Never wake a session merely to inspect it. Delivery acknowledgements are factual receipts, not product acceptance or a prerequisite to another unit.

## Drive and rotation

Drive is off by default. Use `pi-streams drive <id> on` only within a continuous-work grant. Keep drive on after a finite objective while North Star remains unfinished, until verified North Star acceptance, a genuine stop or an authorized cap. Report an unconfirmed remote stop without re-enabling it. A queued goal never answers a human question.

Use `pi-streams rotate <id>` for current Goals and retained handover pickup. The engine stops and drains a busy predecessor before successor admission. A real teardown failure preserves the old owner. Do not bypass pending questions, explicit stops, security or confirmed overlapping writers. At requested SYNC/DUMP, follow the supplied `pi-streams dcr ready` command and yield; do not author RESUME or replay maintenance.

Stale saved openings, journals, checkpoint identities, callback declarations and empty or timed-out rosters are bookkeeping, not live writers. Abandon uncertain historical effects without replay. Continue a new authorized isolated unit rather than requiring historical repair or audit packets. A missing publisher cwd calls for a fresh worktree from the accepted commit, not a silent cwd substitution for an uncertain command. Before publishing the same ref, inspect its current target and use normal fast-forward or compare-and-swap constraints. No forced push or publication authority is added.

Native inference retries keep the same provider, model and thinking. Application SSO is a separate real dependency. Never read tokens, repair credentials, switch provider/model or replay rejected content. Continue unrelated permitted work or retain one concise blocker without repeating it every wake. Do not rearm content-policy-rejected tasks or paraphrase to evade safeguards. Three distinct blocked dispatches without permitted progress suppress an identical fourth prompt.

## Close

Use current Goals, Charter and Rules as authority. Open history/, context/, checks/ and handover/ only on demand. Never inspect engine-only registries, configuration, tick-state, locks or failures/.

1. Identify workers through `pi-streams status <id> --json`.
2. Reuse each worker's existing valid handover. Request a missing handover from that exact session. Its first line is `session: <full-session-id>`. Do not author or relabel another worker's evidence.
3. Verify requested acceptance on the real artifact using sufficient existing checks. A receipt alone does not prove completion.
4. Run `pi-streams close <id>`. Report unresolved live work honestly. Close does not authorize aborting workers or repairing credentials.
5. Append the verified outcome with `pi-streams state append` using a stable request ID and report actual evidence paths.
